# SC Stream Prover

SC Stream Prover is being built to compare stochastic arithmetic observations with explicitly scoped numerical models. This checkout contains repository validation tooling and documentation. Full foundation qualification is in progress. There is no installed arithmetic-analysis package, circuit runner, public arithmetic-analysis command or qualified numerical report.

SC Stream Prover is part of the **SC Neuromorphic Computing Systems** group (SC-NEUROMORPHIC-COMPUTING-SYSTEMS). The [group and project map](https://github.com/anulum/sc-neurocore/blob/main/docs/ecosystem.md) shows the whole programme and where this repository sits in it.

## Boundary

This project owns planned arithmetic experiments, independent circuit oracles, finite error analysis, applicable bound and statistical admission, tested-length selection and its own report. SC-NeuroCore owns the circuit implementations; Randomness Witness owns source batteries and certificates; Loop Timing Witness owns capture and timebase. Evidence Manifest Toolkit supplies shared evidence operations and Experiment Ledger supplies generic storage.

Source batteries, byte identity and pairwise correlation do not establish an entire experiment's numerical assumptions. Simulation and fabric are separate origins. A finite observed error is not a universal error guarantee.

## Current tooling

Seven repository controls inspect metadata, source attribution, workflows, dependency alignment, native documentation, inventory and preflight orchestration. Native-tool bootstrap verifies selected development executable and licence bytes. The descriptor declares architecture-only maturity with empty implemented domain capability and claim inventories.

Use the exact development environment in [Contributing](CONTRIBUTING.md). Named commands are make metadata, make source-provenance, make workflows, make dependencies, make docs, make inventory and make licence. Full CI/preflight belongs in CI or an explicitly admitted pre-push environment. See [Validation](VALIDATION.md) for the scope.

## Intended result

The intended report retains the whole prior experiment and tested sweep, exact finite quantities, unavailable prerequisites, located violations and separate evidence eligibility. A reported minimum identifies the first qualifying tested point under that prior protocol. It does not guarantee that every greater length qualifies; later observed failures remain visible.
